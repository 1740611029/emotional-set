## 【快速同步拉取代码.bat】改为自动撤销本地改动后拉取（用户需求，已完成）

- 文件：`快速同步拉取代码.bat`（项目根目录）。
- 原行为：`git status --porcelain` 统计到未提交改动就打印中止提示 + `pause` + `exit /b 1`，导致同步失败。
- 新行为：检测到改动不再中止，改为 `git reset --hard` + `git clean -fd` 全部撤销本地改动后，照常走 `git fetch fast main` → `git merge --ff-only fast/main` → 同步 origin/main 指针。

- 编辑方式：Python 以 gbk 编码读写（Write/Edit 工具按 UTF-8 会把 GBK 中文化成乱码），临时脚本用完已删除；CRLF 换行保持不变。

### 第二轮修复（用户反馈运行还是旧版报错 + 中文乱码）
- 原因：git reflog 显示 `HEAD@{0}: reset: moving to HEAD`——脚本自身的修改未提交，第一次运行新脚本时 `git reset --hard` 把它自己还原成仓库旧版，故再运行看到的还是中止提示。
- 修复1（自保护）：把无差别 `git reset --hard` / `git clean -fd` 改为带排除——`git reset --hard HEAD -- . ":(exclude)*.bat"` 与 `git clean -fd -e *.bat`，撤销所有改动但保留所有 bat（用 `*.bat` 通配而非中文文件名，规避 GBK 传给 git 的匹配坑）。已验证 exclude 语法生效。
- 修复2（乱码）：在 `@echo off` 后加 `chcp 936 >nul`，控制台切 GBK 匹配文件编码；已用 GBK 解码验证 echo 中文完整。注意此行是纯 ASCII，在 chcp 生效前执行不受编码影响。
- 效果：脚本不再自毁，每次运行即使 bat 自身 modified 也能保住新逻辑；DIRTY 判断会把 bat 自身计入，故每次都走清理分支（符合预期）。
