# Spec Delta

## MODIFIED Requirements

### Requirement: 收盘重算

服务 MUST 在交易日收盘后（15:00 之后）首次运行时触发一次日线重算，并以原子方式更新落盘数据。同一交易日内重复触发 MUST NOT 产生不同结果。重算 MUST 落盘三份产物：指数信号、板块趋势与 ETF 放量事件，MUST NOT 只重建其中两份。

由于行情源常在收盘数小时后才发布，服务 MUST 把「当天已完成」判定为全部参与新鲜度判定的数据线确实覆盖到最近已完成交易日：仍未覆盖时 MUST NOT 把当天标记为完成，并 MUST 在收盘后的固定补齐时刻再试。补齐时刻 MUST 由在用主源实测的日线定稿时刻校准并预先声明，MUST 在健康检查中可见；固定补齐时刻 MUST 只在数据仍落后时才发起远端请求，且同一批积压时刻 MUST 只执行最靠后的一轮，不形成重试风暴。ETF 数据线落后 MUST 同样触发补齐与事件产物重建。

#### Scenario: 收盘后自动重算

- **WHEN** 服务在交易日 15:00 之后启动或运行
- **THEN** 服务 MUST 完成一次日线数据刷新与信号重算，并更新三份落盘产物

#### Scenario: 幂等重算

- **WHEN** 同一交易日已重算过且原始数据未变化
- **THEN** 再次重算 MUST 产出完全相同的结果，且不重复拉取已缓存原始数据

#### Scenario: 源尚未发布时不标记当天完成

- **WHEN** 收盘重算完成后板块日线仍未覆盖最近已完成交易日
- **THEN** 服务 MUST NOT 把当天记为已完成，并 MUST 在下一个固定补齐时刻再次尝试

#### Scenario: 晚间补齐成功

- **WHEN** 到达固定补齐时刻且数据源此时已发布最新日线
- **THEN** 服务 MUST 补齐原始数据、重算并原子落盘三份产物，同时刷新内存快照

#### Scenario: 数据未落后时补齐时刻不发请求

- **WHEN** 到达固定补齐时刻而全部数据线已覆盖最近已完成交易日
- **THEN** 服务 MUST NOT 发起远端请求，并把当天记为已完成

#### Scenario: 仅 ETF 线落后

- **WHEN** 指数、板块、机构均已覆盖最近已完成交易日而 ETF 线落后
- **THEN** 服务 MUST 只补 ETF 线并重建 ETF 放量事件产物，MUST NOT 因「其余已新鲜」而跳过

#### Scenario: 补齐时刻可核查

- **WHEN** 客户端读取健康检查
- **THEN** 响应 MUST 给出当前生效的收盘重算时刻与各固定补齐时刻，且 MUST 与在用主源的定稿时刻记录一致

### Requirement: 健康检查

服务 MUST 提供健康检查端点，返回服务存活状态、最近一次刷新时间、数据模式与所用数据源，并 MUST 暴露数据补齐的可观测信息：当前阶段与说明、最近一次错误、收盘重算尝试次数、当天完成日期与已执行的补齐时刻。健康检查 MUST 额外给出在用主源标识与版本、调度版本、限速器冷却状态，以及每条数据线的本地 `as_of`、最近已完成交易日与落后交易日数。响应 MUST 明确区分「实时快照可用」与「日线已跟上」：仅有前者时 MUST NOT 表示为数据新鲜。

#### Scenario: 健康检查可观测

- **WHEN** 客户端请求健康检查端点
- **THEN** 响应 MUST 包含存活标记、`last_refresh_at`、`mode`、`data_source`、当前算法版本、在用主源标识与调度版本

#### Scenario: 补齐进度可追溯

- **WHEN** 数据正在补齐或补齐失败
- **THEN** 响应 MUST 给出当前阶段与说明，并包含补齐尝试次数、当天是否已完成与已试过的补齐时刻

#### Scenario: 各数据线新鲜度分别可见

- **WHEN** 某条数据线落后而其余数据线已覆盖最近已完成交易日
- **THEN** 响应 MUST 逐线给出 `as_of` 与落后交易日数，MUST NOT 用单一的 `stale=false` 掩盖该落后

#### Scenario: 冷却状态可见

- **WHEN** 限速器处于冷却期
- **THEN** 响应 MUST 给出冷却中的发行方与剩余时长，MUST NOT 把「冷却跳过」报成「数据已覆盖」

#### Scenario: 多机版本可比对

- **WHEN** 两台机器分别读取各自的健康检查
- **THEN** 在同步到同一份代码后，两端的调度版本与在用主源版本 MUST 一致，可直接比对判断是否完成更新

## ADDED Requirements

### Requirement: 收盘与盘中数据所属交易日口径一致

收盘快照与盘中快照的 `as_of` MUST 由同一条预先声明的规则导出，MUST NOT 一个取各指数尾日的最小值、另一个取最大值。规则 MUST 在产物与响应中标注。当各指数尾日不一致时，响应 MUST 显式给出落后的标的与日期，MUST NOT 静默地用一个聚合日期代表全部标的。

#### Scenario: 模式切换不产生日期跳变

- **WHEN** 同一批原始日线在收盘模式与盘中模式下分别生成快照
- **THEN** 两者的 `as_of` MUST 按同一规则得出且可互相解释，MUST NOT 仅因模式不同相差一个交易日

#### Scenario: 短板标的随日期一起返回

- **WHEN** 7 个指数中 1 个尾日落后 1 个交易日
- **THEN** 响应 MUST 同时给出 `as_of`、全部指数尾日与落后标的代码，MUST NOT 只显示聚合日期
