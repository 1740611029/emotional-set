# Design

## Context

动机与范围见 `proposal.md`。本设计只描述实现路径与关键取舍。

现状生产算法为 `index-swing6-v2.0`（`pipeline/swing_signal_engine.py`）：六因子极端度共振产生候选 → 候选日 +1..3 交易日逐日检查价格/动量/量能三层 → 以确认日作为信号日。评价侧 `pipeline/confirmed_index_signals.py:evaluate_signals` 用「信号后到下一个反向信号或段末之前任意时点首次均线反转」判成功，未决剔除分母。

可复用资产（避免重新发明，也避免引入新口径）：

- `pipeline/pivot_algorithms.py` 已有 ZigZag 事后确认制拐点与 `_three_layer_confirm`，其 docstring 已明确「start 传入 zigzag 自然确认日，三层确认不得早于它，否则会用到尚不可知的拐点信息」，且三层判定直接复用生产 `swing_signal_engine.layer_state`。
- `pipeline/pivot_eval.py` 已有冻结评价窗口 `FROZEN_WINDOWS`（M=5、N=8、confirmation_cap=5）与「窗口不得按现行算法偏移分布反推」的约束。
- `data/research/index-pivot-comparison.md` 已有现行算法与拐点算法的 train / validation 对照结果。
- `pipeline/confirmed_index_signals.py` 已有 `drawdown_fields`、`ACTIVE_ALGORITHM` 版本开关、`legacy_accuracy` 兼容层；`pipeline/research_algorithms.py` 已有 `RESEARCH_START=2020-10-30` / `RESEARCH_END=2024-12-31`；`pipeline/schemas.py` 已有 confirmation 日志的 schema 校验。
- 前端 `signal-hub-web/src/data/MarketDataProvider.tsx` 已按 `successes / resolved` 聚合，替换点集中。

硬约束（`AGENTS.md`）：#1 无未来函数、#2 准确率优先、#3 只做本次需求、#5 口径固定、#6 指标可与主流软件对照、#7 调参与验证分离、#8 准确率带样本量、#9 算法变更留痕、#11 三层确认完整、#12 三层日志完整、#13 UI 风格一致。用户已确认的四项口径见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 让信号在**不早于拐点自然确认日**的前提下贴近真实拐点，且信号数不多于旧算法。
- 把「准确率」变成可验收的 5/10/20/30 日持有期矩阵，逐格给出触发次数与样本量。
- 把「控制回撤」变成可验收的成败条件（20 日内最大不利偏移 ≤5%）。
- 在独立验证段给出结论，并保留旧算法可复算对照。

**Non-Goals:**

- 不做盘中/实时信号、不做自动交易、不输出买卖建议或预期收益（与 `live-data-api` 现有约束一致）。
- 不更换数据源、复权方式、板块清单与宽度计算；不改 `market-data-pipeline` 中板块四态评估的 10/20 日口径。
- 不改【指标总览】7 张指数图卡的布局与色彩系统（见 D6 假设）。
- 不引入机器学习模型、外部情绪/资金因子或新价格口径（会带来事后修订与未来函数风险，且需单独评审）。
- 不修正本次需求之外的既有问题（`AGENTS.md` #3）。

## Decisions

**D1 — 拐点结构为主干、六因子为严格化闸门（而非纯 ZigZag 或纯因子加严）**
备选：A 纯 ZigZag 破位信号（信号偏多、噪声大，无法保证「牺牲次数换准确率」）；B 沿用现行六因子仅提高阈值（不解决「信号不在拐点」）；C 拐点主干 + 六因子全部达更高阈值 + 三层确认（选用）。
理由：C 同时回应「贴近拐点」与「宁愿牺牲信号次数」，且 `index-pivot-signal-research` 已规定辅助因子不得否决价格结构已成立的候选——六因子作为闸门而非候选源与该规范兼容。六维权重与阈值只在训练段冻结。

**D2 — 三层确认起点绑定拐点自然确认日，窗口自该日起最多 3 个交易日（含当日）**
备选：起点保持在候选日 +1（会用到尚未可知的拐点，踩 #1）；把窗口压到 0 日（破坏 #11 的确认语义）；绑定自然确认日（选用）。
理由：`pivot_algorithms.py:186-188` 已给出该约束的明确警示；从自然确认日起算仍保留价格 → 动量 → 量能三层全部通过与逐层日志，符合 #11 / #12。代价是信号必然滞后拐点若干交易日，只能做到「滞后但贴近」，**无法在拐点当日无偏发信号**——这是数据本身的限制，不是实现取舍。

**D3 — 主口径改为「固定持有期方向正确 + MAE 5% 硬约束」，替换「任意时点均线反转」**
备选：保留均线反转仅加严（「任意时点」与无限窗口问题仍在）；改用拐点命中率单一口径（不回答用户关心的「后续走势」）；固定持有期矩阵（选用）。
理由：用户明确要求 5/10/20/30 日分别列准确率与触发次数；固定持有期消除了无限窗口与事后择优；把浮亏约束并入成败判定，使「控制回撤」成为可测条件而非旁注。浮亏判定固定用盘中极值的 `max_adverse_excursion_20`，不用收盘价口径，避免放宽。

**D4 — 触发次数恒等于实际信号数，未决显式列示**
现行 `82 触发 / 77 已判定 / 5 未决剔除` 是 97.4% 失真主因之一。新矩阵每格同时输出 `triggers`、`resolved`、`successes`、`failures`、`pending`，`triggers` MUST 与产物中的信号条数一致。未决不进分母但 MUST 可见。

**D5 — 双口径并列：方向正确率 / 有效幅度率（按指数 × 持有期分别冻结幅度线）**
只报一个数字会重演「只展示最宽松口径」的问题。两口径逐格并列、各自带样本量，界面不得混称，也不得表述为交易收益率。用户 2026-11-09 确认：不用统一 1%，改为按每个指数的波动特性分别定线——取训练段（2020-10-30~2024-12-31）全部交易日 H 日绝对收益的 **75 分位**，按 7 指数 × 4 持有期冻结为 **28 条线**，验证段 MUST NOT 调整。实测 20 日线：上证 4.25% / 沪深300 5.08% / 中证500 5.28% / 深证成指 6.01% / 中证1000 6.52% / 创业板 7.98% / 科创50 8.28%；30 日线创业板 10.67%、科创50 10.06%、上证 4.93%。冻结表落 `data/research/`，附每个指数的训练段行数与分位计算依据。

**D6 — 不扩展标的池；生产展示仍为 7 大宽基指数 7 张图卡；界面显式标注统计覆盖范围**
用户 2026-11-09 明确选定：不新增指数、不新增图卡，调参与统计验证均只用固化的 7 大宽基指数。页面仍标注「统计覆盖 7 个标的」，使统计范围与图示范围一致。原 `proposal.md` 的 D6 假设（扩展标的只用于统计、不上图卡）因不再扩展而自动消解，**无需追加 UI 栅格布局变更任务**，`live-data-ui` 现有布局要求保持不变。

**D7 — 训练段 / 隔离期 / 独立验证段三段切分，隔离期 ≥30 个交易日**
最长前瞻窗口由 20 日增至 30 日，隔离期须同步覆盖「30 日前瞻 + 20 日浮亏」叠加跨度。训练段结束日仍固定 `2024-12-31`，不随标的池扩展或数据更新延长；参数只在训练段选取，验证段仅作报告（#7）。

**D8 — 数据口径与标的清单均不变**
指数仍为同花顺公开日线 + 前复权，板块仍为东财 31 个单层行业板块 + 不复权日 K，字段顺序、价格单位与宽度计算不变（#5）。标的清单固定为现有 7 大宽基指数，以独立 manifest 冻结在 `data/research/`，研究期不触碰生产 JSON。

**D9 — 折线图同时区分三个日期**
拐点基准日（事后标注）、拐点自然确认日、信号确认日以不同标记样式呈现并配图例；信号 marker 仍取确认日。用户可直接在图上核对「偏离多少」，而不必依赖一个汇总百分比。

**D10 — 保留 `index-swing6-v2.0` 可复算入口与旧口径基线**
沿用 `ACTIVE_ALGORITHM` 版本开关模式；新旧信号集合与两套准确率口径在同一段历史上并列输出，旧聚合 `rate` 保留为标注「历史基线」的兼容字段（#9）。对照报告必须注明新旧口径不可直接比较。

## Risks / Trade-offs

- **[信号过少导致样本量不足]** → 用户 2026-11-09 逐条确认放宽样本量门槛（见本文末「2026-11-09 口径放宽留痕」）；矩阵逐格仍 MUST 给出触发次数、样本量、Wilson 区间与统计区间，数字一律如实披露，但不再以样本数门槛禁止给出结论。实测独立验证段仅 22 条信号、每格 0~3 条，Wilson 区间极宽（4/4 全对为 [51.0%, 100%]），这些数字 MUST 与结论并列展示，不得掩盖。
- **[5% 浮亏硬约束与贴近拐点叠加后信号可能极少]** → 阈值训练段冻结、验证段不调；若验证段样本过少，按 #8 如实标注并列为待评审事项，MUST NOT 在验证段放宽阈值。
- **[ZigZag 事后确认制实现不当引入未来函数]** → 强制截断自检测试（T 日后数据置空后 T 日及之前信号逐条一致）；三层确认起点不得早于自然确认日；复用 `pivot_algorithms.py` 已审计的实现。
- **[口径更换后新旧准确率被误读为「准确率上升/下降」]** → 对照报告并列两口径并注明不可比；界面旧字段标注「历史基线」。
- **[扩展标的池被误认为更换数据口径]** → manifest 固化数据源/复权/字段；评审记录明确「同类数据源下标的数量扩展，非口径更换」。
- **[图示 7 指数与统计覆盖 N 个标的不一致引发新的不信任]** → 页面显式标注覆盖清单与数量，并区分图示范围与统计范围；三个日期可对照（D9）。
- **[修改指数评价与回撤判定影响板块四态评估等既有产物]** → 指数 `accuracy` / `evaluation` 分支与板块 `evaluation`（研究/验证 × 10/20 日 × 四态）分流，板块结构、字段与口径保持不变；`live-data-api` 的板块评估字段不随本次变更改动。
- **[核心指标数值与主流软件不一致]** → 新增/改动的均线、RSI、量比等指标按 #6 抽样与通达信、同花顺核对后再交付。

## Migration Plan

1. **研究阶段（只写 `data/research/`）**：扩展标的池落盘与 manifest → 重建拐点基准集 → 候选算法对照（含现行 `index-swing6-v2.0`）→ 训练段冻结参数（拐点幅度/间隔、六维闸门、浮亏阈值、有效幅度阈值）→ 隔离期 → 独立验证段出报告 → 输出三态决策结论。运行前后生产 JSON 逐字节一致。
2. **决策闸门（2026-11-09 用户放宽）**：三态结论仍 MUST 输出并附支撑数据、样本量与统计区间；但**无论结论为「更换建议」/「观察」/「保留现行」，均允许继续第 5~7 组**。改动范围界定见本文末「R3 范围界定」。生产信号算法是否切换仍 MUST 在任务 5.2 之前向用户单独确认（`AGENTS.md` #4）；未获该确认前，生产信号记录（日期、类型、价格、条数）保持现行 `index-swing6-v2.0` 不变，仅重建评价与展示结构。
3. **生产切换**：新增算法版本与开关 → 保留旧版可复算 → 扩展 `pipeline/schemas.py` 结构校验 → 重建 `data/index-signals.json`（落盘前保留上一版、原子替换）→ 服务端 `/api/snapshot` 与 history 字段扩展 → 前端矩阵卡片与三日期标记改造（遵循 #13 淡色风格）。
4. **验证**：单元与集成测试（含未来函数截断自检、MAE 硬约束、未决列示、触发次数守恒）、结构校验、抽样指标核对（#6）、新旧对照报告（#9）、三层确认日志完整性检查（#12）。
5. **回滚**：切回旧算法版本开关并恢复上一版产物；前端保留对旧聚合字段的兼容读取，避免回滚后页面报错。
