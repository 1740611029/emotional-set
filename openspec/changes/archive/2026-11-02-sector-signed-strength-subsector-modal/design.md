# Design

## Context

板块四态与强度当前都在 `pipeline/confirmed_sector_trends.py` 计算：`range_position` 和 `ma_score` 先组成 0–100 的基础方向分，`warn` / `bear` 再取反，零通道固定为 50；`pipeline/schemas.py` 同步限制范围并复算取反公式。前端只解释和展示结果，但 `sectorStates.ts` 也复算旧口径用于说明。

`Sectors.tsx` 目前以同一个 `code` 查询参数表示一级或二级选中项，点击二级行会把主详情和走势请求都切到二级，导致一级上下文消失。项目没有现成 Dialog 组件或弹窗依赖，但已有可复用的 `SectorTrendChart`、`StrengthExplainer` 与历史数据 Hook。

## Goals / Non-Goals

**Goals:**

- 用同一份有向强度公式贯串流水线、Schema、API 数据与前端解释，避免只改显示造成口径分裂。
- 在不改变四态、持续天数、历史序列和历史评估的前提下完成强度口径迁移。
- 让一级主详情与二级弹窗拥有独立的选中项、历史请求和时间范围状态。
- 复用现有浅色 UI、状态标签、强度解释和走势图表，不引入新的组件库。

**Non-Goals:**

- 不调整唐奇安通道、MA60、四态阈值或 `sector-donchian20-ma60-v1.0` 判定版本。
- 不修改二级板块历史评估的研究段、验证段、胜率、样本量或稳定性提示。
- 不把走势图改为强度图；主折线仍为收盘价，蓝色虚线仍为 MA60。
- 不为历史逐日强度新增序列，也不改变 API 路径和字段结构。

## Decisions

### 1. 有向强度采用“基础方向分减 50”

保留 `base_strength = (range_position + ma_score) / 2`，统一输出 `strength = base_strength - 50`，范围裁剪到 -50–+50；零通道仍先按异常处理，但最终有向强度固定为 0。`range_position` 与 `ma_score` 继续导出 0–100，避免改变构成分含义。

选择减 50 而不是简单给旧强度加负号，是因为旧强度已在空头/退潮状态取反，直接加负号会保留“越负反而越强”的矛盾。减 50 后，数值符号直接对应原始方向分相对中性的位置，且所有状态使用同一公式。

`strength_basis` 仅保留 `directional` 和 `neutral`：有效状态统一为 `directional`，零通道为 `neutral`，无有效状态时为空；不再生成 `inverted`。四态算法版本不变，因为本次只改变派生展示指标的表示方式，不改变状态判定。

### 2. 数据校验和前端解释以公式为唯一口径

Schema 同步把 `strength` 范围改为 -50–+50、异常中性值改为 0，并按 `directional` / `neutral` 复算。前端删除取反说明和“跨状态不可比”提示，改为展示统一算式及正负含义；排序直接按有符号数值降序，空值和异常项置尾。

服务端不转换旧数据，也不提供双口径兼容字段。构建产物必须先完成迁移再供新前端读取，避免同一快照混有 0–100 与 -50–+50 两种数值。

### 3. 一级选中与二级弹窗使用独立 URL 状态

保留 `code` 表示当前一级板块，新增 `sub` 表示弹窗中的二级板块。点击二级行只设置 `sub`，不再覆盖 `code`；关闭弹窗只移除 `sub`。筛选、检索或切换一级板块时同时清除 `sub`，避免隐藏弹窗仍持有旧二级代码。

这样既能保留一级上下文，也能通过 URL 恢复“一级页面 + 二级弹窗”的组合状态。主详情和弹窗分别调用历史 Hook、分别保存 60 / 120 / 250 日范围，弹窗范围默认 120 日，避免两个图表互相切换。

### 4. 使用原生 dialog 与现有展示组件

新增轻量二级详情弹窗组件，使用原生 `<dialog>` 的模态能力处理焦点、Escape 和背景遮罩，并提供显式关闭按钮；样式沿用现有玻璃卡片、浅绿主色和四态色彩，不新增依赖。

弹窗内容复用状态标签、父级差异提示、`StrengthExplainer` 和 `SectorTrendChart`。主详情继续展示一级板块，二级表格和历史评估面板继续留在背景页面；评估是全二级板块汇总，不伪装成单个二级板块的专属评估。

### 5. 用同一份原始日线做前后对照

迁移前保留当前 `sector-trends.json` 基线，迁移后用同一批原始 CSV 重建。对照分为两类：

- 必须完全不变：一级/二级 `state`、`days`、分组归属、历史 `close` / `state` 序列和评估结果。
- 只能按口径转换变化：`strength` 与 `strength_basis`。旧 `directional` 的新值应为旧值减 50；旧 `inverted` 的新值应为 50 减旧值；旧 `neutral` 的新值应为 0。

同时覆盖典型样例：基础分 80 → 30、基础分 20 → -30、零通道 → 0，验证正负方向和边界。

## Risks / Trade-offs

- [旧缓存与新前端混用会把旧 50–100 数值误读为有向强度] → 发布时先备份并重建产物，再启动新服务和新前端；Schema 对旧公式与旧中性值直接报错。
- [有符号降序会让偏强板块靠前、偏弱板块靠后，不再表示“当前状态方向最强”] → 界面明确标注“有向强度”，排序按原始有符号值，不取绝对值。
- [弹窗与主详情同时请求历史会增加一次请求] → 仅在 `sub` 存在时请求二级历史，关闭后立即停止使用该请求；沿用现有数据层错误和陈旧降级。
- [提取共用详情展示可能带回一级主页面回归] → 优先组合现有组件而非重写图表，分别验证一级详情、二级弹窗、关闭恢复和独立时间范围。

## Migration Plan

1. 备份改动前的板块趋势产物，并记录用于对照的原始数据日期。
2. 修改流水线与 Schema，运行强度、四态不变性、历史序列及评估不变性测试。
3. 使用同一原始数据重建产物，生成前后对照并确认只有预期字段变化。
4. 更新前端强度解释和排序，再接入独立二级弹窗；完成组件交互与构建验证。
5. 以新产物启动服务并交付新前端。回滚时必须同时恢复旧代码与旧产物，禁止只回滚其中一侧。
