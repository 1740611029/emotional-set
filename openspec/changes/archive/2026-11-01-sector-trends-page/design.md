# Design

## Context

现状与约束（动机见 `proposal.md`，行为契约见 `specs/`）：

- 数据层已落地：`integrate-live-market-data` 已归档，`pipeline/`（板块判定 `confirmed_sector_trends.py`、产物组装 `build_dashboard.py`）、`server/`（`snapshot.py`、`app.py`）、`data/`（`index-signals.json` 931KB、`sector-trends.json` 24KB）与前端 `src/data/{types,client,MarketDataProvider}` 均已存在。`/api/snapshot` 每 30 秒轮询，已有 `stale` / `data_state` / `progress` 降级语义。
- 板块四态判定：`sector_state()` 以唐奇安 20 日通道中轨（`close > (HH20+LL20)/2`）与 MA60 两条判据组合四态，有效样本需 60 日；`strength` 由通道位置百分比与 MA60 偏离的 `tanh` 映射各占一半，空头/退潮取反；`days` 为状态连续保持交易日数。
- `build_sectors()` 当前输出：`groups{bull,warn,bear,rise,unclassified}` → `{code, name, strength, days, subsectors[{name, strength, days}]}`。**状态仅体现在分组键上，条目内无 `state`/`date`；二级板块无 `code`；无任何价格序列。**
- 二级板块 `state`/`days` 当前直接赋值父级，仅 `strength` 独立（`confirmed_sector_trends.py:135`）。实测：131 个二级板块全部具备足够历史（`calculate_sector_trend` 有效状态数均 > 0，原始行数最少 171、中位 3068），去掉继承后 **21 个状态与父级不同**（110 个一致）；`strength` 本就用自身状态取反计算，故数值不变。
- 二级独立四态的历史方向胜率实测（`evaluate_sector_states` + `summarize_sector_events`，按 `type` 分组）：研究段（2020-10-30~2024-12-31）20 日胜率 bull 46.1%（样本 4350）、rise 48.0%（3890）、bear 58.4%（4643）、warn 55.4%（3580）；验证段（2025-01-01 起）bull 51.8%（2471）、rise 59.8%（1887）、bear 47.0%（2339）、warn 53.2%（2081）。**符号在两段之间翻转，无稳定方向优势。**
- 强度样例（用于解释面板文案）：银行 bull 89.1 = (区间位置 100.0 + MA60 分 78.1)/2；半导体 bear 98.8 = 100 − (1.9 + 0.5)/2；食品加工 bear 61.8 = 100 − (41.8 + 34.6)/2（空头但位置已回区间中部，故强度偏弱）。
- `server/app.py` 已有 `/api/indices/{code}/history`，返回 `history` + 信号集合；无板块历史路由。
- 前端未安装图表库；`src/data/types.ts` 的 `SectorItem` 无 `state` 字段；**目前没有任何页面消费 `sectors`**，本页是首个消费方。
- AGENTS.md 第 1、2、4、5、9 条：禁止未来函数、准确率第一、影响信号逻辑须先报告、口径固定、算法变更留痕。

## Goals / Non-Goals

**Goals:**

- 把已有判定结果做成可浏览、可对照的板块视图；四态**判据**不动，仅把二级板块的状态来源从"继承父级"改为"自身日线独立判定"。
- 让"走势"可用：为每个板块提供可对照日线的收盘 + 状态序列，且序列末项与该板块条目的 `date` / `state` 严格一致。
- 让"强度"可解释：把 0–100 的含义、取反规则与两项构成分直接呈现在界面上，而不是留给用户猜。
- 保持 30 秒轮询成本不变：快照不因新增走势能力而膨胀。
- 单一数据源：走势序列、状态摘要与强度构成出自同一份 `sector-trends.json`，不存在第二套计算。

**Non-Goals:**

- 不新增或调整四态判据、阈值与 `strength` 公式。
- 不提供板块成分股、资金流、相对强弱排名。
- 不做盘中板块实时行情（沿用既有设计：板块走日线，盘中只更新 `as_of`）。
- 不重构现有页面与设计系统。

## Decisions

### D1. 图表库选用 ECharts，单实例 `setOption` 驱动

**决策**：新增 `echarts` 依赖，按需引入 `LineChart` + `GridComponent` + `TooltipComponent` + `MarkAreaComponent` + `DataZoomComponent`，封装 `SectorTrendChart`；实例只创建一次，切换板块或范围时 `setOption`，卸载时 `dispose`。

**理由**：需要"收盘折线 + MA60 + 四态背景色带 + 十字光标 + 缩放"五类能力，ECharts 的 `markArea` 与 `axisPointer` 可原生表达，且后续指标详情页可复用同一套主题封装。

**备选**：纯 SVG 自绘 → 缩放、命中测试、色带分段都需自建，长期成本更高；Recharts → 无 `markArea` 等价物，色带要拆成多段面积图，与状态序列对齐易错。

**代价**：体积增加约 300KB（gzip 后约 100KB）；通过按需引入与 `React.lazy` 路由级懒加载控制首屏。

### D2. 单一数据源、两种视图：文件存 250 日序列，快照瘦身，端点切片

**决策**：

- `data/sector-trends.json` 顶层新增共享 `dates: string[]`（最近 250 个交易日），每板块新增 `close: number[]`、`state: string[]`（与 `dates` 对齐，单字母码 `B/W/D/R`，空为 `null`）、`spark: number[]`（最近 30 日收盘）、`date`、`data_anomaly`、`data_lag`、`strength_parts`、`strength_basis`；二级板块补充 `code`。
- `/api/snapshot` 的 `sectors` **剔除** `dates`/`close`/`state` 三个长序列，只透传摘要字段与 `spark`，保持轮询体量不变（增量约 40KB）。
- 新增 `GET /api/sectors/{code}/history?days=60|120|250`，从同一份 JSON 按 `days` 切片返回，不重新计算。

**理由**：30 秒轮询若内嵌 162 × 250 的全量序列，响应体会膨胀到约 400KB 且每 30 秒重复传输；瘦身快照 + 按需切片把成本降到只在切换板块时发生一次。所有视图仍出自同一文件，不产生第二套计算。

**备选**：全量内嵌快照 → 轮询成本不可接受；端点从 `data/raw/` 现算 → 引入运行时重算与原始数据依赖，且可能与落盘产物不一致，否决。

**体积核算**：162 板块 × 250 日 × (收盘 ~8 字符 + 状态 1 字符) ≈ 365KB，加现有 24KB 约 390KB。已提交的 `index-signals.json` 为 931KB，量级可接受。

### D3. 状态色带用 `markArea` 分段，由状态序列压缩为连续区间

**决策**：前端把 `state[]` 压缩为 `[{from, to, state}]` 连续区间，映射为 `markArea` 数据项；四态配色 `bull` 薄荷绿、`rise` 天蓝、`warn` 浅珊瑚、`bear` 珊瑚，透明度约 0.12。颜色从 `index.css` 的 CSS 变量读取（`getComputedStyle`），不在 JS 重复硬编码。

**理由**：`markArea` 按 x 轴区间着色，天然对齐交易日；压缩后 250 个点通常只剩 5–15 个区间，渲染与图例语义都更清晰。

**备选**：逐日 `custom` 矩形 → 点密集时性能与噪点都差；按状态拆多条面积图 → x 轴不连续，切换处断裂。

### D4. 二级板块独立判定，去掉继承覆盖

**决策**：删除 `calculate_sector_universe()` 中"二级板块 `state`/`days` 赋值父级"的分支，二级板块改用自身日线跑同一 `calculate_sector_trend()`；保留"父级名称必须存在"的校验。滞后板块不再因为"与父级日期不一致"报错，改为按自身 `date` 输出并标记 `data_lag`；滞后超过 30 个自然日时 `state` 置空。

**理由**：用户需要看到板块内部分化（例如家用电器一级为 `rise`，而黑色家电/小家电/厨卫电器等 6 个子板块为 `bear`），继承口径会把这种分化完全抹平。技术成本极低：131 个二级板块的有效历史全部 ≥ 60 日，判定函数无需改动。

**代价与约束**：二级独立四态的历史方向胜率在研究段与验证段之间符号翻转（见 Context），说明它**没有稳定预测优势**。因此产物必须附带分状态评估（样本量 + 分段 + Wilson 区间），页面必须披露该结论；这是"能展示"与"能当信号用"的分界线。

**备选**：保留继承 + 标注 → 抹平分化，正是用户要解决的问题；二级单独设计一套判据 → 需重新调参与独立验证，超出本次范围且违背口径固定原则。

### D8. 强度的呈现：数值 + 口径 + 两项构成分

**决策**：产物导出 `strength_parts{range_position, ma_score}` 与 `strength_basis`；页面强度旁提供"如何解读"入口，展开后显示：

1. 口径说明：0–100，50 中性；`bull`/`rise` 未取反（越高=上行方向越强），`bear`/`warn` 已取反（越高=下行方向越强）。
2. 构成分解：两项分数 + 可复算算式。例：银行 `directional` 89.1 = (100.0 + 78.1)/2；半导体 `inverted` 98.8 = 100 − (1.9 + 0.5)/2。
3. 使用边界：强度只在同一状态内可比，跨状态不可比；`data_anomaly` 时固定为 50。

**理由**：`strength` 是"通道位置 + MA60 偏离"的合成值且对空头取反，不解释就会被当成"看涨分数"误读（空头 98.8 会被读成极度强势）。导出两项构成分而非只写文案，使解释可被数值验证，也满足 AGENTS 第 6 条"结果可对照"的精神。

**备选**：只写一段说明文字 → 无法验证、也无法定位"为什么这个板块强度高"；把强度拆成两个独立指标展示 → 与既有产物口径不一致，且增加阅读负担。

### D9. 算法变更留痕：一级零变化 + 二级变化清单

**决策**：`confirmed_sector_trends.py` 新增 `sector_history(frame, days)`、`strength_parts` 计算与 `subsector_evaluation`；`build_sectors()` 负责组装。对照沿用 `pipeline/compare_snapshot.py`，但口径改为**两段判定**：31 个一级板块必须逐条零变化（任何差异视为回归失败）；131 个二级板块的 `state`/`days` 变化必须输出完整清单（代码、名称、旧状态、新状态）。

**理由**：AGENTS 第 9 条要求算法变更留痕。一级不变是"没改坏"的证明，二级变化清单是"改了什么"的证明，两者缺一不可。

**备选**：统一要求"全部相等" → 与本次变更目的矛盾；只比总数 → 无法追溯具体板块。

### D5. 布局"左列表 + 右详情"，筛选排序在客户端

**决策**：桌面端两栏（左 320px 列表，右详情）；四态筛选 chip、强度降序、名称/代码检索全部在内存完成；筛选与选中状态写入 URL query 以便分享与刷新还原。

**理由**：总量 162 条，客户端筛选零延迟且不扩展服务端契约。

**备选**：服务端筛选 → 为 162 条数据引入查询参数、缓存与一致性成本，收益为零。

### D6. 色彩语义沿用项目既有系统，不改为 A 股红涨绿跌

**决策**：四态配色沿用 `index.css` 既有语义（薄荷绿 = 上行、珊瑚橙 = 下行），与 `Indices.tsx`、`ui.tsx` 保持一致。

**理由**：AGENTS 第 13 条要求新增页面遵循既有色彩系统；单页反转语义会造成站内同一颜色两种含义。

**已知偏差**：与 A 股"红涨绿跌"习惯相反。若需纠正，应作为全站色彩语义变更单独评审，本次不做。

### D7. 页面通过统一数据层接入

**决策**：板块摘要消费 `MarketDataProvider` 已提供的快照（不新增请求逻辑，自动获得 30 秒刷新、可见性暂停与陈旧降级）；走势序列由 `useSectorHistory(code, days)` 单独拉取。页面组件不出现任何硬编码业务数值。

**理由**：`live-data-ui` 的"单一数据源"要求页面复用同一数据层；把取数集中在 hook 内，接口变化不影响页面。

**备选**：页面内直接 `fetch` → 重复实现轮询与降级逻辑，违反单一数据源约束。

## Risks / Trade-offs

- **[落盘文件增大]** `sector-trends.json` 从 24KB 增至约 390KB → 快照侧剔除长序列，轮询成本不变；文件仍在 1MB 以内，与 `index-signals.json` 同量级。
- **[快照与端点时点不一致]** 快照 `as_of` 已更新但端点仍读上一版文件 → 端点返回自身 `as_of`，页面在两者不一致时显示"走势数据截至 X"，不静默混用。
- **[二级独立状态被当成信号]** 用户看到 131 个板块各有状态，容易认为都有预测力 → 评估数据随产物输出并在页面披露"研究段/验证段符号翻转、无稳定优势"，且不提供任何信号触发语义。
- **[跨状态强度被误比]** 空头 98.8 与多头 89.1 放在一起排序会被读成"半导体最强" → 排序时显示跨状态不可比提示；默认视图按状态分组呈现。
- **[强度被当成看涨分]** 取反规则不直观 → 解释面板显式标注"取反/未取反"并给出两项构成与算式。
- **[二级与父级不一致引发困惑]** 一级 `rise` 而子板块 `bear` → 行内显示"与所属一级板块（反转）不一致"，并在父级详情给出子板块状态分布摘要。
- **[图表实例泄漏与切换抖动]** 频繁切换板块 → 单实例 + `setOption` + `dispose`；切换时 `showLoading` 避免闪烁。
- **[250 日档依赖落盘长度]** 若某板块可用历史不足 250 日 → 端点返回实际长度并标注覆盖区间，页面按实际长度绘制，不补值。
- **[数据滞后]** 个别二级板块最新交易日早于 `as_of` → 条目带 `data_lag` 与自身 `date`，页面提示；滞后超 30 自然日直接置空状态，不沿用旧值。

## Migration Plan

1. 先固化基线：把当前 `data/sector-trends.json` 复制为 `data/research/sector-trends-baseline.json`（旧继承口径）。
2. 改 `pipeline/`（二级独立判定、强度构成、历史序列、二级评估）→ 重新生成产物 → 跑对照：一级 31 条零变化，二级输出变化清单（预期 21 条）。
3. 扩展 `server/`（快照瘦身 + 新路由）→ 用现有快照与历史端点做接口自测。
4. 前端接入（类型、hook、图表、页面、导航）→ 用真实数据验收。
5. 回滚：移除 `/sectors` 路由与侧边栏项即可回退前端；服务端新路由为新增，旧字段未删；若需回退二级独立判定，恢复基线产物与 `calculate_sector_universe()` 的继承分支即可，一级结果不受影响。
