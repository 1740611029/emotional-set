### 事件簇级别使用后置数据

`pipeline/etf_volume_events.py` 的 `identify()` 把簇内最高级别写入 `events.level`；`forward_stats()` 再按该级别分层，从 `start_date` 起算收益。以后几日才能知道的 L3 因而会被用于更早簇首日的收益分组。

本次已用两日合成数据离线复现，不读写行情文件：第一日仅一只成交额达到 100 亿元，第二日六只均达到 100 亿元。

```python
import sys
sys.path.insert(0, 'pipeline')
from etf_volume_events import identify
import pandas as pd

dates = ['2026-11-02', '2026-11-03']
frames = {
    str(i): pd.DataFrame({
        'date': dates,
        'amount': [1e10 if i == 0 else 0, 1e10],
    })
    for i in range(6)
}
history = pd.DataFrame({'date': dates, 'close': [100, 101]})
for label, source in [
    ('cut', {code: frame.iloc[:1] for code, frame in frames.items()}),
    ('full', frames),
]:
    print(label, [(row['start_date'], row['level'])
                  for row in identify(source, history)['events']])
```

实际输出：

```text
cut [('2026-11-02', 'L1')]
full [('2026-11-02', 'L3')]
```

- 这不是逐日 `days` 标记计算的未来函数，而是事件簇级别被回标、随后被用于收益分层的问题。
- 现有 `NoLookaheadTest` 在两个簇都已结束后才截断，没有覆盖仍在延长、后续可能升级的簇。
- 旧报告实际将 2024-09-30、2026-11-03 的 L3 纳入首日分别为 2024-09-24、2026-10-15 的簇。这两个首日不能被解释为当日已经知道六只全部放量。
