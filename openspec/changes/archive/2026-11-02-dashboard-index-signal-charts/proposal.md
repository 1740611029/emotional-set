# Proposal

## Why

现有【指标总览】以统计卡片和文字表格为主，用户难以直接看出信号在真实行情中的位置；【宽基指数】页面也只有卡片汇总，信息停留在描述层。把七个指数的走势与已确认、待确认信号放在同一视图中，可以减少重复页面，并让用户直观看到信号出现前后的行情关系。

## What Changes

- **BREAKING**：移除侧边导航中的【宽基指数】入口、前端 `/indices` 路由与对应页面；旧地址自动跳转到【指标总览】，不再单独提供指数卡片列表。
- 【指标总览】的图表主区改为指数信号图表区：同一区域并排展示 7 大指数，每张卡片包含指数名称、当前收盘、涨跌幅和一条真实收盘价折线；桌面布局为每行两张，第 7 张独占末行，其他断点保持响应式换行。
- 原有顶部汇总、最新信号列表和待确认候选列表保留作为辅助信息；原有“信号分布”和“近 30 日信号趋势”两个统计块被新的指数信号图表主区取代，避免与新图表重复展示同一批数据。
- 每张指数图在折线上叠加信号标记：已确认底部信号与已确认顶部信号分别使用方向语义和视觉形态区分；当前处于确认窗口内的候选信号也必须显示，并与已确认信号明确区分。
- 图表上方提供统一的时间范围下拉框，选项为：近一个月、近三个月、近半年、近一年、近两年、近三年、全部。一个选择同时作用于 7 张图。
- 时间范围按实际交易日对现有快照历史截断；“全部”展示快照中已有的完整历史，并显示实际覆盖区间与交易日数量。
- 信号悬停信息至少包含日期、方向、状态、触发价；候选信号还须显示价格、动量、量能三层确认进度。盘中临时数据继续展示既有盘中提示。
- 默认时间范围按“近一年”设计；该默认项仅为初始展示值，不改变信号计算或评价口径。
- “还没确认的信号”仅指当前仍在确认窗口内的候选信号；已过期、失败或未成功确认的历史候选不在现有快照数据中，本次不新增此类历史数据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `live-data-ui`: 将【指标总览】的行为改为七张指数走势与信号标记视图，移除独立【宽基指数】入口，并规定统一时间范围、信号状态区分及盘中/候选展示。

## Impact

- 前端影响：`signal-hub-web/src/pages/Dashboard.tsx`、`signal-hub-web/src/pages/Indices.tsx`、`signal-hub-web/src/components/Sidebar.tsx`、`signal-hub-web/src/App.tsx`，并新增可复用的指数信号图表组件与相关类型。
- 数据层与 API：继续使用 `/api/snapshot` 中每个指数的 `history`、`signals` 与 `candidates` 字段；不新增接口，不修改信号计算、候选确认机制或准确率统计。
- 依赖：使用现有 `echarts`，不新增前端依赖。
- 兼容性：`/indices` 路由不再展示独立页面，旧地址重定向到 `/`；这是对外可观察的导航变化。
- 测试：补充图表时间截断、信号状态映射、候选标记区分与路由导航的测试；保留现有 `npm run build` 验证。
