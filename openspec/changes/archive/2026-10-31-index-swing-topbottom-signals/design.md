# Design

## Context

见 `proposal.md` 的 Why。设计需要基于以下既有事实与约束：

- 现有实现：`multifactor_research.confirmed_multifactor_signals()` 生成候选，`_check_confirmation()` 做三层确认，信号日期记为**确认日**（不是候选日），因此不存在"用未来数据发信号"的问题；评价在 `confirmed_index_signals.evaluate_signals()` 中完成。
- 胜率口径（已由用户确认沿用）：`research_algorithms.ma_reversal_masks()` 要求 MA5>MA10>MA20>MA30 且四条均线同时向上（顶部反之）。判定区间从信号日之后一直到**下一个反向信号日或数据末尾**，没有时间上限。这解释了为什么 80 个信号几乎全部成功：只要在下一个顶部信号出现前出现过任意一次多头排列即算成功，而反向信号往往在数月之后。
- 可用数据：7 大宽基指数日线（2020-10-30 起，约 1450 个交易日），申万行业日线 162 个文件（一级 + 二级，`data/raw/sectors/first|second`）。无成分股、无估值、无资金流历史序列。
- 现有研究基建可复用：`wilson_interval()`、`evaluate_window()`、`apply_embargo()`、`training_score()`（Wilson 下界）、`RESEARCH_START/RESEARCH_END`。

## Goals / Non-Goals

**Goals:**

- 用 6 个相互正交的方向做共振筛选，使信号不再等价于"超卖 + 反弹"。
- 引入横截面宽度，这是当前完全缺失且公开研究中最具解释力的维度。
- 用波段交替状态机替换固定冷却期，保证一个波段只有一个转折信号。
- 保持主胜率口径不变，使新旧算法可在同一口径下并列对比。
- 所有阈值经训练段确定、验证段评估，结论可复现。

**Non-Goals:**

- 不改动数据源、复权口径、落盘路径与 API 契约。
- 不改动前端页面与视觉规范（新增字段的展示属后续独立需求）。
- 不引入机器学习模型、不引入估值/资金流/成分股数据。
- 不优化盘中 `provisional` 快照逻辑，本次只影响收盘正式信号。

## Decisions

### D1：六方向正交因子，取代四因子加权

**做法**：每个方向独立计算 0–1 得分，合成分数为加权和。方向定义如下（`b` 为底部方向，`t` 为顶部方向）：

| 方向 | 核心量 | 标准化方式 |
|---|---|---|
| 价格位置 | 距 250 日高点回撤（b）/ 距 250 日低点涨幅（t）；RSI14；布林 %B；20 日 z-score | 250 日滚动分位，取分位值本身（0–1） |
| 动量背离 | 价格创 20/60 日新低（高），而 RSI14、MACD 柱、OBV 三者未同步创新低（高） | 背离成立个数 / 3 |
| 量能极值 | 成交量 / 20 日均量；OBV 5 日斜率；MFI14 变化 | 20 日均量比的 250 日分位；斜率做符号化处理 |
| 波动状态 | ATR14 / close 的 250 日分位；布林带宽 250 日分位 | 分位值本身 |
| 趋势状态 | MA60 斜率、MA120 斜率、ADX14、价格相对 MA250 位置 | 分段线性映射到 0–1 |
| 横截面宽度 | 站上 MA20 行业占比、站上 MA60 占比、5 日变化 | 占比取分位；变化量线性映射 |

**为什么不是简单加权求和**：单纯加权会让"超卖 + 下跌"两项同时高分而误触。因此加两道闸门：

1. **核心闸门**：`价格位置`、`横截面宽度`、`量能极值` 三项中至少 2 项达到极端区（分位 ≤0.15 或 ≥0.85，方向按 b/t 取）。
2. **否决闸门**：`趋势状态` 处于"加速恶化"（MA60 斜率分位 ≤0.1 且 ADX 上升）时，底部候选直接否决；顶部对称。这是为了避免在下跌加速段抄底。

合成分数 `score = Σ w_i · s_i`，权重先验取等权（各 1/6），研究阶段在 `{等权, 位置加权, 宽度加权}` 三组中选一组，选定后冻结。

**实现校准（与初稿的差异）**：方向得分是多个子项的平均，分布被压缩（`score_bottom` 中位数约 0.42、标准差约 0.13），初稿设的"分位 ≥0.85"闸门在 6 年样本里只命中 4 天，实际不可用。实现改为按**方向得分本身**取阈值：核心闸门 `≥0.60`、合成分数 `≥0.52`，由研究脚本在训练段网格 `{0.55,0.60,0.65} × {0.50,0.52,0.55}` 中选出，选中组合的候选量约为每指数 20 个。

**替代方案**：直接沿用四因子并调阈值——被否，因为 `exhaustion` 内部四项高度相关，调阈值只是移动同一条曲线。

### D2：宽度用申万一级行业截面，按交易日聚合

**做法**：对每个交易日 T，取所有在 T 日有数据的申万一级行业收盘价，计算：

- `breadth20(T)` = 行业收盘 > 该行业 MA20 的比例
- `breadth60(T)` = 行业收盘 > 该行业 MA60 的比例
- `breadth_delta5(T)` = `breadth20(T) - breadth20(T-5)`

行业 MA 用各行业自身序列的滚动均值，不使用指数数据替代。可用行业数 <20 时该维度置空并按 D1 的权重归一规则重算（见 spec `横截面宽度`）。

**为什么不用全市场个股宽度**：项目无逐日历史成分股与退市股行情，用当前名单倒推历史会引入生存偏差（`multifactor_research.advanced_data_review()` 已记录该结论）。行业指数是历史可得的替代口径。

**替代方案**：用 akshare 涨停家数/融资余额——被否，历史序列不稳定且难以保证 point-in-time 一致性，先不做。

### D3：波段交替状态机 + 最小波段约束

**做法**：维护 `last_signal` 状态（`bottom` / `top` / `none`）。

- 若 `last_signal != "top"`，只接受底部候选；若 `last_signal != "bottom"`，只接受顶部候选。
- 同向候选在未出现反向信号前一律丢弃（不是延后，是丢弃）。
- 新增最小波段约束：自上一个反向信号以来，价格振幅 ≥ `min_swing_amplitude`（先验 3%）且间隔 ≥ `min_swing_days`（先验 8 个交易日），否则视为噪声波段，不予确认。

**为什么替换固定冷却期**：固定 20 日冷却允许同向连续触发，与"波段"语义冲突；交替约束天然保证一个波段一个信号，且信号数量由市场自身节奏决定，不需要人为设定频率。

**替代方案**：保留冷却期并加大到 60 日——被否，只是把问题推后，且会在长下跌段里仍然发出多个底部信号。

### D4：确认层保留三层结构，但判定量改为结构突破

现有确认用"收盘 > MA5 + 阳线 + OBV/MFI 斜率"，在震荡市里 MA5 极易被反复穿越，确认太松。新确认改为：

| 层 | 底部 | 顶部 |
|---|---|---|
| 价格确认 | 收盘 > 候选日最高价（结构突破） | 收盘 < 候选日最低价 |
| 动量确认 | 收盘 > 开盘 且 RSI14 较前一日上升 | 收盘 < 开盘、RSI14 下降，**且 MA5 已掉头向下** |
| 量能确认 | 成交量 ≥ 1.2 × 5 日均量，或 `breadth_delta5` ≥ +5pp | 成交量 ≥ 1.2 × 5 日均量，或 `breadth_delta5` ≤ -5pp |

确认窗口仍为 1–3 个交易日，超时作废。**信号日期记为确认日**（沿用现状），因此页面展示的信号价格是确认日收盘价，不是候选日价格。

**顶部动量层额外要求 MA5 掉头的理由**：仅用"阴线 + RSI 回落"确认时，顶部信号出现后 20 日平均收益为 +1.02%（即价格仍在上涨），属于过早发出。加入 MA5 转向后，训练段由 +0.57% 降至 +0.33%、验证段由 +2.51% 降至 -0.02%，两段同时改善，且信号数量不变（确认日会后移）。底部不加此条件：底部的反转更急，要求均线转向会显著漏掉 V 型底（实测训练段底部 20 日收益由 +1.06% 降至 -0.92%）。

**为什么量能层对底部允许"宽度改善"替代放量**：缩量阴跌型的底部在确认日往往没有明显放量，强行要求放量会漏掉这类底部；宽度改善是同一逻辑的另一种表达（参与度回升）。

### D5：分级 A/B

- `A`：核心三项（价格位置 / 横截面宽度 / 量能）全部达到极端，且合成分数不低于本指数信号的中位数。
- `B`：其余已确认信号。

**实现调整**：初稿要求"A 级还需确认日为窗口第 1 天且分数在前 1/3"，实测三项核心同时极端只占 23/73，叠加"次日即确认"后只剩 4 个 A 级样本，无法做分组统计。改为"核心三项全极端 + 分数不低于中位数"，得到 16 个 A 级样本，A/B 对比才具备最低可用的样本量。
- 分级阈值在训练段确定后冻结，验证段不再调整。

分级的意义是让页面能区分"强共振"与"标准"信号，并使评价可以按级别分别统计。

### D6：评价保留主口径，新增诊断字段

主胜率仍走 `ma_reversal_masks()`，判定区间、未决处理、分段边界全部不变。新增诊断字段（不进入主分母）：

- `forward_return_5/10/20`：信号后第 5/10/20 个交易日收盘相对信号价的收益
- `max_adverse_excursion_20`：20 日内相对信号价的最大不利偏移
- `days_to_confirmation`：到均线反转的天数（已有字段）

另新增 `baseline_rate`：同期随机取等量日期、按同一主口径计算的成功率，与信号成功率并列。

**为什么不改主口径**：用户已明确选择沿用，且改动会使新旧算法不可比。诊断字段用于暴露"胜率高但收益薄"的情况，而不替换主口径。

### D7：研究流程与选参

- 训练段：`2020-10-30` ~ `2024-12-31`（固定，与 `RESEARCH_END` 一致）。
- 验证段：`2025-01-01` ~ 数据最新日。
- 隔离期：20 个交易日（`EMBARGO_DAYS`），覆盖最长前瞻窗口。
- 候选池：每个方向 2–3 个变体，共约 12–18 个因子；组合方式为"全量六方向"与"去掉单方向"各一版，用于检验每个方向的边际贡献。
- 选参指标：`min(底部 Wilson 下界, 顶部 Wilson 下界)`，已判定样本 <20 的组合直接淘汰（复用 `training_score()`）。
- 稳定性约束：入选组合必须在 ≥4 个指数上表现出正超额（信号 20 日前瞻收益高于同期全样本均值），否则视为过拟合。**注意**：此处用 20 日超额收益而非"胜率高于基准率"——后者在均线反转口径下的基准率高达 0.75，任何信号都很难超过，会把所有组合误判为无效。
- 实际结果：`core_extreme=0.60, score_threshold=0.52` 在训练段取得最高 Wilson 下界（底部 1.00 / 顶部 0.95），且 6/7 个指数为正超额；网格中其余组合或因训练段样本不足、或因一致性不足被淘汰。验证段结果只记录、不回炉。
- 输出：`data/research/swing-factors-<version>.json`，含冻结参数、训练/验证对照、淘汰原因、输入哈希。

### D8：回撤作为第二口径贯穿所有页面

**做法**：回撤分两处使用，边界必须严格区分。

1. **信号生成侧（可用，但只能是历史回撤）**：`价格位置` 方向使用 `close / rolling(250).max() - 1` 的滚动分位，这是截至信号日已发生的回撤，不涉及未来。
2. **评价侧（事后，禁止回流）**：以信号日收盘价为基准，计算
   - `max_adverse_excursion`：至确认日（未决至区间末）的最大不利偏移，底部用最低价、顶部用最高价；
   - `max_adverse_excursion_20` / `max_drawdown_20`：固定 20 日窗口；
   - `forward_return_5/10/20`；
   - 汇总层：`avg_max_adverse_excursion`、`worst_max_adverse_excursion`、`avg_forward_return_20`、`return_drawdown_ratio`。

**为什么用最低/最高价而不是收盘价**：波段交易的真实持仓成本要按盘中极值承受浮亏，只用收盘价会低估回撤。因此 `max_adverse_excursion` 用极值，`max_drawdown_20` 用收盘价，两者并列，避免单一指标误导。

**为什么回撤不进入胜率**：用户已定主口径为均线反转。回撤进入分母会改变历史可比性。因此回撤只做并列展示与排序依据，不改变 `success` / `failure` / `pending`。

**页面约束**：仪表盘胜率卡片、指数卡片、指标详情、信号明细表，凡出现胜率或收益，必须同屏出现回撤；无样本时显示 `--`，不得显示 0。

**替代方案**：只用收益/回撤比作为单一综合指标——被否，比值在平均回撤接近 0 时会爆炸，且掩盖尾部风险（最差回撤），必须同时展示均值与最差值。

### D9：模块划分

- `pipeline/swing_indicators.py`：纯计算，输入单指数 OHLCV + 可选宽度序列，输出逐日因子表。无 I/O、无全局状态。
- `pipeline/swing_signal_engine.py`：候选生成、状态机、三层确认、分级，输出与现有 `signals` Series 兼容的结构 + 明细。
- `pipeline/research_swing_factors.py`：离线研究脚本，只写研究目录。
- `pipeline/confirmed_index_signals.py`：`confirmed_signals()` 改为调用新引擎；`evaluate_signals()` 增加诊断字段与基准率，主口径逻辑不动。
- `pipeline/schemas.py`：新增信号明细字段校验。

## Risks / Trade-offs

- **过拟合** → 粗网格 + Wilson 下界 + 跨指数一致性约束 + 训练/验证隔离；验证段结果不理想时保留原参数并如实报告，不回炉调参。
- **样本量过少导致置信区间过宽** → 接受这一代价；以跨指数合并样本为主结论，同时强制展示分项（spec 已要求）；单指数单方向样本 <30 时标注小样本。
- **主胜率口径天然偏乐观（无时间上限）** → 不改口径，但用 `days_to_confirmation` 与前瞻收益诊断字段暴露真实质量；报告中明确说明该口径不含时间约束。
- **宽度数据起点不一** → 以"可用行业数 ≥20"为门槛，早期交易日宽度维度置空并重算权重；输出标注缺失，不用零值填充。
- **波段交替导致信号大幅减少，可能出现"一年无信号"** → 这是波段语义的必然结果，不人为补信号；页面需能表达"当前无信号"状态（现有 `current_signal.type = none` 已支持）。
- **状态机对历史重算敏感** → 一旦某个早期信号因数据修订而消失，后续交替链会整体改变。缓解：原始数据固定、不自动补值（沿用现有约束），并在输出中记录输入哈希。
- **2020–2024 训练段只覆盖一轮完整熊牛** → 验证段（2025–2026）是唯一的样本外证据，结论需标注为"单次样本外"，不宣称长期稳定。

## Migration Plan

1. 新引擎与旧算法并存：`confirmed_index_signals.ACTIVE_ALGORITHM` 作为唯一开关，`"swing"` 走新引擎、`"legacy"` 走四因子旧实现，两套代码同时保留。
2. 先产出对照报告（旧 vs 新，同口径、同区间、样本量与成功率并列），人工确认无未来函数、无异常信号后再切换生产入口。
3. 切换 `ACTIVE_ALGORITHM = "swing"` 并升级 `ALGORITHM_VERSION`；`data/index-signals.json` 重新构建。
4. 回滚：把 `ACTIVE_ALGORITHM` 改回 `"legacy"` 并重建数据即可，新旧产物路径一致，无需数据迁移；`SIGNAL` schema 的扩展字段为可选，因此旧算法的输出仍能通过校验。

## Open Questions

- 分级 A 的比例阈值（前 1/3）是否合适，需在研究阶段观察 A 级样本量后确定；若 A 级样本 <10 个则放宽到前 1/2。
- 申万二级行业是否纳入宽度计算（可把样本从 31 扩到 130+，但二级行业相关性强，可能不增加信息量），留待研究阶段用信息增量检验决定。
