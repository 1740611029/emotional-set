# lhb-traders-view Specification

## Purpose
定义【龙虎榜知名游资】页对「已清仓 / 疑似清仓 / 已离场」配对的展示时效契约：让游资总览与个股游资总览在默认视图下只保留近 5 个交易日的离场信息，同时提供共用的可按需回看开关，使每日动向保持原有展示不变，且不改变产物数据与判定算法。

## Requirements

### Requirement: 游资总览与个股游资总览的 5 交易日展示窗口

【游资总览】（卡片与游资详情）与【个股游资总览】MUST 默认只展示离场判定成立日距数据截至日 **不超过 5 个交易日**的（游资, 个股）配对，两个 Tab MUST 使用同一阈值、同一份可见集合，MUST NOT 再保留 3 个交易日的过滤线。天数 MUST 以产物 `trading_dates` 中 `exit_date` 与 `as_of` 的序号差计算，MUST NOT 按自然日、MUST NOT 按最后上榜日计算。`已清仓`、`疑似清仓`、`已离场` 三种状态 MUST 适用同一阈值，MUST NOT 因状态不同而区别对待。窗口内的配对 MUST 同时展示其操作记录与离场状态标记；在场（`active`）配对 MUST 始终展示，不受本窗口限制。

游资详情页（点入单个游资后的操作记录表格）MUST 使用与卡片列表相同的可见集合：卡片列表与详情页 MUST 共用同一份受显示开关控制的视图，MUST NOT 为详情页创建独立的过滤参数或硬编码 `includeExpired` 值。开关关闭时两者同时隐藏超期配对；开关开启时两者同时回显。

#### Scenario: 恰好 5 个交易日仍展示

- **WHEN** 数据截至日为 `2026-11-13`，某配对的 `exit_date` 为 `2026-11-06`（在交易日序列中相隔 5 个交易日）
- **THEN** 该配对 MUST 同时出现在【游资总览】与【个股游资总览】中，且 MUST 带有其对应的离场状态标记

#### Scenario: 第 6 个交易日起默认隐藏

- **WHEN** 数据截至日为 `2026-11-13`，某配对的 `exit_date` 为 `2026-11-05`（在交易日序列中相隔 6 个交易日），且显示开关处于默认关闭状态
- **THEN** 该配对的全部操作记录 MUST NOT 出现在这两个 Tab 中，MUST NOT 以占位行、空行或灰色行代替

#### Scenario: 三种离场状态一视同仁

- **WHEN** 三个配对的离场天数同为 6 个交易日，状态分别为 `已清仓`、`疑似清仓`、`已离场`
- **THEN** 三个配对 MUST 全部被默认隐藏；当显示开关开启时三者 MUST 全部回显，MUST NOT 只回显其中某一种状态

#### Scenario: 在场配对与多日榜口径不受影响

- **WHEN** 某配对状态为 `active`，或其记录属于多日累计榜
- **THEN** 在场配对的记录 MUST 照常展示；多日累计榜 MUST 继续沿用既有「只存记录、不参与金额统计」约定，MUST NOT 因本窗口被额外隐藏或额外计入

#### Scenario: 开关关闭时详情页不含超期配对

- **WHEN** 显示开关处于关闭态，用户从卡片列表点入某游资详情页
- **THEN** 该详情页的操作记录表格 MUST NOT 含有 `exit_date` 距 `as_of` 超过 5 个交易日的离场配对记录，MUST NOT 展示对应的离场状态标记

#### Scenario: 开关开启时详情页回显超期配对

- **WHEN** 显示开关处于开启态，用户从卡片列表点入某游资详情页
- **THEN** 该详情页的操作记录表格 MUST 含有超期离场配对的记录与离场状态标记，与卡片列表的可见集合一致

#### Scenario: 切换开关后详情页即时反映

- **WHEN** 用户在游资详情页按返回回到卡片列表，切换显示开关后再点入同一游资
- **THEN** 详情页的操作记录集合 MUST 与新的开关状态一致，MUST NOT 残留上一状态的过滤结果

### Requirement: 5 交易日外离场个股的显示切换开关

【游资总览】与【个股游资总览】MUST 各提供一个「显示 / 隐藏 5 日外离场个股（N）」切换按钮，两个按钮 MUST 共享同一个开关状态：在任一 Tab 切换后，另一个 Tab MUST 同步呈现相同状态。按钮初始状态 MUST 为**隐藏**（即不展示超期配对）。开启时 MUST 回显全部被隐藏的配对及其离场状态标记；再次关闭 MUST 恢复到默认隐藏集合。切换 MUST 只影响这两个 Tab 的可见性，MUST NOT 重新请求数据、MUST NOT 修改任何数值、MUST NOT 改变离场状态判定、MUST NOT 改变【每日动向】。按钮标签 MUST 以「5 日外离场个股（N）」的形式给出 **N = 当前被默认隐藏的（游资, 个股）配对所涉及的去重股票代码数**的精确计数；N MUST 直接取自过滤结果，MUST NOT 插值、推算或展示分位/环比等衍生量。若某股票同时存在可见配对与被隐藏配对，该股票 MUST 仍计入 N（因为开关会改变该行内容）。

#### Scenario: 默认进入页面为隐藏态

- **WHEN** 用户首次进入【游资总览】或【个股游资总览】Tab
- **THEN** 页面 MUST 只展示窗口内配对，两个 Tab 的按钮 MUST 均处于「隐藏」态，且按钮标签 MUST 显示按上款定义精确计得的 N

#### Scenario: 开启后回显历史离场个股

- **WHEN** 用户在任一 Tab 点击按钮开启显示
- **THEN** 超过 5 个交易日的配对 MUST 在这两个 Tab 中连同其操作记录与离场状态标记一并出现，窗口内配对 MUST 保持原有展示与标记，MUST NOT 出现重复行

#### Scenario: 两处按钮状态同步

- **WHEN** 用户在【游资总览】开启显示后切换到【个股游资总览】
- **THEN** 后者按钮 MUST 显示为开启态且展示集合 MUST 已包含超期配对，MUST NOT 需要再次点击

#### Scenario: 关闭后恢复默认集合

- **WHEN** 用户再次点击任一按钮关闭显示
- **THEN** 两个 Tab 的展示集合 MUST 与开启前完全一致，MUST NOT 残留超期配对，MUST NOT 改变【每日动向】或各 Tab 的排序状态

#### Scenario: 计数随过滤结果精确变化

- **WHEN** 产物新增一个交易日导致部分配对跨过 5 日边界
- **THEN** 按钮标签的 N MUST 等于按新 `as_of` 重新过滤后被隐藏配对涉及的去重股票代码数，MUST NOT 沿用上一交易日的计数

### Requirement: 每日动向保持既有展示口径不变

【每日动向】MUST 保持本变更之前的展示行为：继续使用既有的 **3 个交易日**过滤视图及其离场标记口径，MUST NOT 改用 5 日阈值、MUST NOT 渲染切换按钮、MUST NOT 受开关状态影响。已核实现有实现中该 Tab 的 `dailyRows` 与另两个 Tab 共用同一份过滤结果，因此「保持原样」在本变更中意味着它消费独立的 3 日视图，而非完全不过滤。系统 MUST 容忍由此产生的差异：第 4~5 个交易日的配对在游资总览与个股游资总览可见，在每日动向中按既有口径隐藏，此差异 MUST NOT 被自动「对齐」。

#### Scenario: 开关不影响每日动向

- **WHEN** 用户在【游资总览】或【个股游资总览】反复切换显示开关后进入【每日动向】
- **THEN** 该 Tab 每个日期的行集合与离场标记 MUST 与改动前逐日完全一致，MUST NOT 出现 5 日窗口带来的新增行，MUST NOT 出现切换按钮

#### Scenario: 每日动向基线可核对

- **WHEN** 以当前产物 `as_of = 2026-11-13` 渲染【每日动向】
- **THEN** 其可见单日榜操作记录总数 MUST 与改动前的 3 日过滤结果一致（实测 355 行；若改用 5 日会变成 432 行）

### Requirement: 数据异常时保守展示

当展示时效无法被可靠判定时，系统 MUST 采取「保守展示」而非「保守隐藏」：以下任一情况 MUST 视为不受窗口约束并照常展示该配对——`exit_date` 为 `null` 或不在 `trading_dates` 中、`as_of` 为 `null` 或不在 `trading_dates` 中、`trading_dates` 为空、旧版产物缺少 `positions` 字段、或 `exit_date` 晚于 `as_of`。系统 MUST NOT 因日期解析失败而隐藏、丢弃或伪造记录。该规则 MUST 同时适用于 5 日视图与 3 日视图。

#### Scenario: 离场日不在交易日序列

- **WHEN** 某配对带有非 `active` 状态，但 `exit_date` 未出现在 `trading_dates` 中
- **THEN** 该配对 MUST 照常展示，MUST NOT 被计入「5 个交易日外」的隐藏集合

#### Scenario: 旧版产物缺少在场状态

- **WHEN** 接口返回旧版产物，`traders[].positions` 字段缺失
- **THEN** 所有配对 MUST 按无离场状态照常展示，页面 MUST NOT 报错、留白或把全部记录判为超期

#### Scenario: 数据尚未就绪

- **WHEN** 页面处于加载中、失败或 `preparing` 状态
- **THEN** 页面 MUST 保持既有加载/错误/准备中提示，MUST NOT 渲染切换按钮或据空数据计算出「0 只」并展示

### Requirement: 金额与计数统计随展示集合同步

【游资总览】的卡片统计（活跃天数 / 操作笔数 / 买入合计 / 卖出合计 / 净买入）与【个股游资总览】的「合计净买入 / 买入 / 卖出」、「在场游资」列表与「共 N 只个股」MUST 仅基于**当前可见**的单日榜操作记录聚合，延续既有「展示什么就统计什么」约定。切换显示开关因此导致这些数值同步变化时 MUST 保持自洽，MUST NOT 出现「行已显示但金额未计入」或「行已隐藏但金额仍计入」。系统 MUST NOT 借本次变更新增任何胜率、准确率、分位、环比或前瞻衍生指标。

#### Scenario: 隐藏时不计入金额

- **WHEN** 某超期配对被默认隐藏
- **THEN** 其单日榜买卖金额 MUST NOT 计入对应游资卡片统计与个股合计净买入，该个股的「在场游资」列表 MUST NOT 含该游资；若该股因此无任何可见记录，则该股 MUST 从表格中消失且「共 N 只个股」相应减一

#### Scenario: 显示时统计同步纳入

- **WHEN** 用户开启显示使该超期配对回显
- **THEN** 其金额 MUST 纳入对应游资卡片统计与个股合计净买入，该游资 MUST 出现在「在场游资」列表并带离场标记，「共 N 只个股」MUST 与表格行数一致

### Requirement: 产物数据与判定口径不变

本变更 MUST 只作用于前端展示层：产物 `data/lhb-traders.json` 中的 `positions`、`exit_date`、离场状态、金额与 `trading_dates` MUST 保持原值，服务端 `/api/lhb/*` 响应结构 MUST 不变。系统 MUST NOT 重新判定离场、MUST NOT 改写 `SILENT_PROBABLE` / `SILENT_FORCED` / `HEAVY_SELL_RATIO` / `TURNOVER_COVER_X` 等阈值、MUST NOT 让任何顶部/底部信号、板块趋势或候选状态计算读取本页的展示结果。

#### Scenario: 开关前后产物与接口不变

- **WHEN** 用户多次切换显示开关
- **THEN** 页面 MUST NOT 发起除既有 `/api/lhb/overview` 之外的新请求，产物与接口返回值 MUST 与切换前逐字段一致

#### Scenario: 口径说明文案同步

- **WHEN** 用户查看页面顶部的统计口径说明，或读取产物 `scope_note`
- **THEN** 文案 MUST 准确描述「游资总览与个股游资总览 5 个交易日且可切换显示、每日动向保持既有 3 个交易日口径」的分 Tab 说明，MUST NOT 继续笼统声称「标记保留 3 个交易日，之后不再展示」
